📋 LO QUE SOLICITASTE:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

❌ PROBLEMA ANTERIOR:
   → Notificaciones hardcodeadas en useState
   → Eliminar notificación → reaparece al recargar F5
   → No conectado a base de datos

✅ SOLUCIÓN IMPLEMENTADA:
   → Tabla "notificaciones" en PostgreSQL
   → Notificaciones persistentes (no desaparecen)
   → Eliminación real (no reaparecen)
   → Se generan automáticamente
   → Se cargan desde API en tiempo real
   → Se actualizan cada 5 segundos
   → Se marca como leído correctamente

🎯 FUNCIONALIDADES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. ELIMINACIÓN SIN REAPARICIÓN
   → Usuario click en × de notificación
   → DELETE /api/notificaciones/:id se ejecuta
   → Se borra de BD (PostgreSQL)
   → Recarga página (F5)
   → ✅ NO reaparece (fue eliminada)

2. AUTO-GENERACIÓN
   → Técnico resuelve ticket
   → Backend crea: Notificacion(titulo="✅ Ticket resuelto", ...)
   → Se inserta en BD automáticamente
   → Usuario ve notificación sin hacer nada

3. TIEMPO REAL CON AUTO-REFRESH
   → Notificaciones se cargan cada 5 segundos
   → No necesita F5 para ver cambios
   → Se sincroniza con BD
   → Muestra contador de no leídas

4. MARCAR COMO LEÍDO
   → Usuario click en notificación
   → PUT /api/notificaciones/:id/read se ejecuta
   → Se marca leído en BD
   → Punto azul desaparece
   → Se guarda permanentemente

TABLA NOTIFICACIONES (PostgreSQL):
  id_notificacion  INT           PK
  id_usuario       INT           FK → Usuario
  id_ticket        INT           FK → Ticket
  titulo           VARCHAR       "✅ Ticket resuelto"
  mensaje          VARCHAR       "Tu ticket TKT-001 ha sido..."
  tipo             VARCHAR       ticket_resuelto, ticket_asignado, etc.
  leido            BOOLEAN       false = no leído, true = leído
  fecha_creacion   TIMESTAMP     Cuándo se creó
  fecha_lectura    TIMESTAMP?    Cuándo se marcó como leído

API ENDPOINTS:
  GET    /api/notificaciones           → Obtener todas
  PUT    /api/notificaciones/:id/read  → Marcar una como leída
  PUT    /api/notificaciones/read-all  → Marcar todas leídas
  DELETE /api/notificaciones/:id       → Eliminar una
  DELETE /api/notificaciones           → Eliminar todas

GENERACIÓN AUTOMÁTICA:
  • Ticket asignado → "🔧 Ticket asignado" (azul)
  • Ticket resuelto → "✅ Ticket resuelto" (verde)
  • Cambio de estado → "📋 Ticket actualizado" (amarillo)

PASO 1: INICIAR SISTEMA
  $ cd backend && npm run dev           # Backend :3000
  $ npm run dev                         # Frontend :5173

PASO 2: ACCEDER A NOTIFICACIONES
  Abrir: http://localhost:5173/usuario/notificaciones

PASO 3: VER DATOS DE PRUEBA
  Debería haber 3 notificaciones:
  • ✓ Ticket resuelto (no leído) - color VERDE
  • 🔧 Ticket asignado (no leído) - color AZUL
  • 📋 Ticket actualizado (leído) - color AMARILLO

PASO 4: PROBAR FUNCIONALIDADES
  a) ELIMINAR:
     - Click en × de una notificación
     - ✅ Desaparece inmediatamente
     - Recarga página (F5)
     - ✅ NO reaparece (está eliminada de BD)

  b) MARCAR COMO LEÍDA:
     - Click en notificación con punto azul
     - ✅ El punto azul desaparece
     - ✅ Se guardó en BD

  c) AUTO-REFRESH:
     - Dejar página abierta por 5+ segundos
     - ✅ Se actualiza automáticamente
     - No necesita F5

  d) LIMPIAR TODO:
     - Click botón "Limpiar todo"
     - Confirmar diálogo
     - ✅ Todas se eliminan

ESCENARIO: Técnico resuelve ticket

1. TÉCNICO HACE LOGIN
2. TÉCNICO VE TICKET EN DASHBOARD
3. TÉCNICO CAMBIA ESTADO A "RESUELTO"
4. ENVÍA PUT /tickets/:id
5. BACKEND updateTicket() DETECTA CAMBIO
6. CREA NOTIFICACIÓN AUTOMÁTICAMENTE
   notificationsController.createNotification(
     userId = solicitante,
     titulo = "✅ Ticket resuelto",
     mensaje = "Tu ticket TKT-001 'Problema con...' ha sido resuelto",
     tipo = "ticket_resuelto"
   )
7. INSERTA EN BD ✅
8. USUARIO ABRE /usuario/notificaciones
9. FRONTEND GET /api/notificaciones
10. CARGA DATOS DESDE BD (PostgreSQL)
11. MUESTRA NOTIFICACIÓN VERDE
12. USUARIO PUEDE:
    • Hacer click para marcar como leída (se guarda en BD)
    • Hacer click en × para eliminar (se borra de BD)
    • Dejar abierta = auto-refresh cada 5s

⚠️  NOTAS IMPORTANTES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Las notificaciones se crean AUTOMÁTICAMENTE
   → No necesitas crear manualmente
   → Backend lo hace cuando técnico resuelve/asigna

2. Eliminar = Eliminar de BD
   → Click × = DELETE /api/notificaciones/:id
   → Se borra de BD (no soft delete)
   → NO reaparece al recargar

3. Auto-refresh cada 5 segundos
   → Frontend GET /api/notificaciones cada 5s
   → Se sincroniza con BD
   → Mejorable con WebSocket (Fase 3)

4. Autenticación requerida
   → Header: Authorization: Bearer {token}
   → Token en localStorage
   → Si expira → error 401

5. Cada usuario ve solo SUS notificaciones
   → Filtro por id_usuario en BD
   → API retorna solo notificaciones del usuario autenticado
